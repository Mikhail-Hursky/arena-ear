# Звук и размер груза

Обновление 5 ноября 2026 года. [Проверенные источники и границы полноты каталога](catalog-sources.md).

## Библиотека без настройки

`BUILTIN_REFERENCES` готов синхронно из `merchant-features.json`. Начало анализа не требует ни загрузки личных файлов, ни 76 сетевых запросов, ни создания AudioContext для подготовки эталонов. OGG воспроизводятся обычным браузерным проигрывателем по запросу пользователя в демо.

Манифест содержит версию 56-компонентного дескриптора, длительность, частоту декодирования и SHA-256 каждого исходного OGG. Тесты проверяют соответствие файлов и манифеста. При замене звуков разработчик запускает генератор через изолированный Chrome:

```sh
PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs node scripts/generate-builtin-features.mjs
```

## Сопоставление

1. `classifyFeatures` сравнивает звук с эталонами. Семейства выше выбранного порога и в пределах отрыва 0,025 сохраняются в `alternatives`. Поднятие и опускание одной группы не создают конкурирующие группы.
2. В начале звука фиксируются выбранная/визуально связанная ячейка, размер, карта, поколение захвата и эпоха сетки. Изменение выбора, размеров, области или режима отменяет незавершённую привязку.
3. `resolveItemMatch` пересекает кандидатов допустимых звуковых групп с точным размером **ширина × высота**. В магазине ориентация фиксирована: 2 × 3 и 3 × 2 — разные размеры. Поворот кандидатов не допускается.
4. Размер по кадру принимается только при confidence ≥ 0,75 и свежей детекции. Ручной размер означает явное подтверждение ширины и высоты пользователем. Сгенерированная ручная сетка 1 × 1 ничего не говорит о размере предмета.
5. Один кандидат означает единственную подходящую запись **в текущем каталоге**. Несколько кандидатов остаются списком; нулевое пересечение даёт конфликт и просьбу проверить границы. Размер не превращает тишину, слабый звук или конкурирующую личную запись в установленный предмет.

App не накапливает доказательства по одному лишь ID позиции: после перемещения в ту же позицию может попасть другой предмет. Модуль поддерживает пересечение предыдущего наблюдения для вызывающего кода с подтверждённой идентичностью, но экранный анализатор его не использует.

## Автовыбор по кадру

Сканер получает кадры примерно каждые 120 мс; геометрию пересчитывает примерно каждые 650–750 мс. Для каждой ячейки берутся 6 × 6 внутренних RGB-патчей с усреднением 3 × 3 пикселя. Перед привязкой нужны два стабильных кадра и локальное изменение только одного прямоугольника с заметным отрывом от соседей. Свежесть кадра ограничена 250 мс, изменения — 350 мс. При начале звука читается ещё один текущий кадр.

Это эвристика изменения изображения, не перехват курсора игры. Одновременное изменение двух ячеек не назначает звук; массовое изменение от 35% прямоугольников очищает прежний вид. Локальные изменения убирают старые подписи затронутых ячеек. Потеря решётки удаляет доверенные размеры; отключение сканирования переводит их в ручные. Неудачная привязка оставляет звуковой результат без записи в произвольную ячейку.

При сомнении пользователь выбирает прямоугольник в панели или на превью, подтверждает размер и повторяет звук. Движение мыши по интерфейсу браузера не выдаётся за наведение в игре. Прокрутка, музыка, наложенные звуки, закрытые рамки и сильно меняющееся изображение могут потребовать ручной проверки. Независимая оценка точности на размеченных игровых записях не проводилась.
