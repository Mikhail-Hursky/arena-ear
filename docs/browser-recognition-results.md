# Проверка совместного распознавания в браузере

Дата: **5 ноября 2026 года**. Изолированный Chrome, локальный Vite-сервер `http://127.0.0.1:5173`. Все перечисленные сценарии проходят.

## Воспроизведение

Сначала запустить `npm run dev`. Для проверки используется отдельная установка Playwright разработчика, без добавления зависимости в приложение:

```sh
PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs node tests/browser-recognition.mjs
```

Каждый раздел запускается в собственном пустом browser context. Пользовательские данные основного браузера не затрагиваются. Все созданные дорожки и AudioContext освобождаются; браузер закрывается и при ошибке.

## Реальный аудио- и видеотракт

Вместо системного диалога `getDisplayMedia` возвращается поток, составленный из `canvas.captureStream()` и реальной аудиодорожки `MediaStreamAudioDestinationNode`. Дальше работают настоящие `GridScanner`, `AudioEngine`, `AudioWorklet`, выделение события, признаки, классификация, совместный отбор и React UI. Ответы распознавателя и видео-детектора не подменяются.

Canvas содержит контрастную сетку 8 × 8 с прямоугольником 3 × 2 на позиции `cell-1-1`: внутренние разделители удалены, внешняя рамка сохранена. После стабильных кадров меняется только внутреннее заполнение этого прямоугольника; через 50 мс настоящий OGG поднятия группы 28 воспроизводится через захватываемую аудиодорожку. Это проверяет временную привязку изменения кадра к звуку без ручного выбора ячейки.

## Границы проверки

Это воспроизводимая проверка всей цепочки на синтетическом изображении и настоящей эталонной записи, а не измерение точности на реальной игровой сессии. Почти единичное сходство ожидаемо при воспроизведении самого эталона; оно не является вероятностью предмета. Не проверены фоновая музыка, речь, одновременно звучащие предметы, реальное движение курсора, частично закрытые границы, прокрутка настоящего инвентаря и доступность системного звука на разных ОС. Решение о единственном предмете остаётся ограниченным текущим проверенным каталогом.
